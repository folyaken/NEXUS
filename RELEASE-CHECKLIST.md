## 🔴 Блокеры — без них установленная версия работает неправильно

### 1. ~~Ядра Xray и sing-box попадут внутрь `app.asar`~~ ✅ исправлено (патч 33)

Самая серьёзная проблема.

`package:win` скачивает ядра в `modules/bin/`, а в `build.files` указано
`modules/**/*`. Значит `xray.exe` и `sing-box.exe` окажутся **внутри архива
`app.asar`**. Это read-only контейнер: операционная система физически не может
запустить исполняемый файл оттуда.

При этом `VpnManager.binPath()` ищет ядро по пути
`process.resourcesPath/modules/bin/xray.exe` — то есть **вне** asar, где его не
будет.

Что увидит пользователь: установил приложение, нажал «Подключить» — VPN не
стартует, начинается повторная загрузка ядра из интернета. Установщик при этом
весит на 40 МБ больше из-за файлов, которыми нельзя воспользоваться.

**Решение:** вынести бинарники в `extraResources` и исключить из `files`.

```jsonc
"files": [
  "dist/**/*", "dist-electron/**/*", "assets/**/*", "package.json",
  "modules/**/*",
  "!modules/bin/**",        // бинарники не должны попадать в asar
  "!modules/logs/**",
  "!modules/configs/**"
],
"extraResources": [
  { "from": "assets", "to": "assets", "filter": ["nexus-tray.png", "nexus-app.png", "nexus.ico", "tray/**/*"] },
  { "from": "modules/bin", "to": "modules/bin" }   // ядра рядом с exe, запускаемые
]
```

### 2. ~~Права администратора не запрошены~~ ✅ решено (патч 34)

Принято решение: приложение **всегда** запускается с правами администратора.
Без них не работают ни Zapret (драйвер WinDivert), ни TUN-режим, поэтому
заставлять пользователя вручную перезапускать программу бессмысленно.

Сделано:

- `win.requestedExecutionLevel: "requireAdministrator"` — запрос прав вшит в
  манифест exe, Windows поднимает UAC сама при запуске;
- `nsis.perMachine: true` — установка для всех пользователей;
- `signAndEditExecutable` заменён на `signExecutable: false`. Первый флаг
  отключает правку ресурсов целиком, вместе с уровнем запуска: настройка прав
  молча не применилась бы. Второй пропускает только подпись кода (сертификата
  пока нет), оставляя манифест и иконку.

Проверка прав в коде сохранена как страховка: у portable-сборки манифест
применяется не всегда, а `npm start` в среде разработки идёт с обычными правами.

Побочный эффект: приложение нельзя добавить в автозагрузку Windows штатным
способом — задачи с повышением требуют планировщика заданий. Учесть, если
понадобится автостарт вместе с системой.

### 3. ~~Персональные данные утекают в установщик~~ ✅ исправлено (патч 33)

`modules/configs/vpn/` содержит профили VPN пользователя (в них ключи и UUID),
`modules/logs/` — журналы. Каталог `modules/**/*` тянет их в сборку целиком.

Если собрать установщик на машине, где приложение уже запускалось, **твои личные
VPN-ключи уедут вместе с ним всем пользователям.**

**Решение:** исключения `!modules/configs/**` и `!modules/logs/**` из пункта 1.
Обязательно проверить содержимое asar перед публикацией.

## 🟡 Важное — иначе продукт выглядит незаконченным

### 4. Автообновление не реализовано

`checkNexusUpdate()` возвращает заглушку `status: 'placeholder'` и
`canInstall: false`. Кнопка «Проверить обновления» в разделе «О программе» ничего
не делает.

Для продукта на рынке это обязательный пункт: пользователи не будут скачивать
zip вручную. Нужен `electron-updater` + публикация релизов на GitHub.

Побочный эффект: без автообновления любой найденный баг остаётся у всех
пользователей навсегда.

### 5. ~~Версия захардкожена в интерфейсе~~ ✅ исправлено (патч 35)

`src/renderer/App.tsx` содержит `NEXUS v1.1.1` строкой и `nexusVersion: '1.1.1'`
в демо-данных. После первого же повышения версии интерфейс будет врать.

**Решение:** брать значение из `app.getVersion()` (метод `about:get-info` уже
это делает — надо использовать его и в боковой панели).

### 6. ~~Нет файла лицензии~~ ✅ сделано (патч 36)

- `LICENSE` — проприетарные условия, правообладатель NEXUS;
- `THIRD-PARTY-NOTICES.md` — компоненты, правообладатели, ссылки на исходники;
- поля `license`, `author`, `build.copyright` в манифесте;
- `nsis.license` — условия показываются шагом установки;
- раздел «О программе» и README содержат сводку.

Лицензии проверены по официальным репозиториям, а не по справочникам. Важное:
GitHub показывает лицензию sing-box как «Other», и только в тексте видно, что
это **GPL-3.0 с дополнительным условием** — производные работы не вправе
использовать имя проекта.

Ключевое решение: sing-box и остальные ядра **не входят в установщик**. Они
загружаются с официальных репозиториев при первом использовании, поэтому NEXUS
не выступает распространителем GPL-программы, а связь идёт через запуск
отдельного процесса, а не линковку. Это снимает требование открывать исходный
код NEXUS.

При добавлении новых компонентов проверять лицензию в репозитории и не включать
копилефт-компоненты в дистрибутив.

### 7. ~~Демо-данные видны при первом запуске~~ ✅ исправлено (патч 35)

`DEMO_MODULES`, `DEMO_LOGS`, `DEMO_UPDATES` показываются до ответа от main-процесса.
Пользователь на долю секунды видит выдуманные записи журнала («Сканирование
завершено: найдено модулей — 4») и фальшивые версии обновлений.

Мелочь, но на демонстрации продукта выглядит несерьёзно. Лучше показать скелет
загрузки.

## 🟢 Желательное — качество и доверие

### 8. Подпись кода (code signing)

Без подписи Windows SmartScreen покажет «Неизвестный издатель» и красное
предупреждение. Значительная часть пользователей на этом остановится — особенно
учитывая, что приложение просит права администратора и работает с сетью.

EV-сертификат стоит денег (~300–400 $/год), но для VPN-продукта это фактически
обязательно. Сейчас стоит `signAndEditExecutable: false`.

### 9. Антивирусы будут срабатывать

Zapret манипулирует TCP-пакетами, TUN создаёт адаптер — типичное поведение,
которое эвристики помечают как угрозу. Стоит заранее:

- отправить сборку на проверку в Microsoft (Windows Defender false positive);
- проверить установщик на VirusTotal;
- описать в README, почему антивирус может ругаться.

### 10. Английская локализация

`language: 'ru'` зафиксирован в типах, весь интерфейс на русском. Это сразу
ограничивает рынок. Инфраструктуры для перевода нет — строки вшиты в компоненты.

### 11. Размер установщика

`node_modules` весит 363 МБ. В сборку пойдёт не всё, но стоит проверить итоговый
размер и убедиться, что devDependencies не попали.

### 12. Проверить, что удаление чистит за собой

NSIS по умолчанию не удаляет `%APPDATA%\nexus-network-tools`. Нужно решить:
спрашивать пользователя или оставлять настройки (второе привычнее).

Отдельно: при удалении должны останавливаться запущенные `winws.exe` и
`TgWsProxy.exe`, иначе они останутся висеть в памяти.

## Порядок работы

1. Пункты 1–3 (блокеры) — обязательно до первой сборки.
2. Собрать тестовый установщик, **проверить на чистой виртуальной машине**:
   установка → запуск → VPN → Zapret → обновление → удаление.
3. Пункты 4–7 — до публичного релиза.
4. Пункты 8–12 — по мере готовности.

Отдельно: проверить содержимое `app.asar` перед публикацией командой
`npx asar list release/win-unpacked/resources/app.asar`, чтобы убедиться, что
личных данных и бинарников там нет.
