# Перенос NEXUS в чистый репозиторий

Пошаговая инструкция. Цель — новый репозиторий, в котором нет ни следа
прежнего окружения: ни в файлах, ни в истории коммитов, ни в названиях веток.

---

## Почему именно перенос, а не чистка на месте

В текущем репозитории следы остались в **истории git**, а не в файлах:

| Где | Что |
| --- | --- |
| Два старых коммита | в `package.json` был идентификатор приложения с чужим доменом |
| Подпись коммита `bfef363` | строка `Co-authored-by` со служебной учётной записью |
| Названия веток | пять веток вида `arena/…` |
| Заголовки PR #1 и #2 | названия тех же веток |

Из истории это убирается только полным её переписыванием. Но даже после него
старые коммиты остаются доступны на GitHub по прямой ссылке, пока сервер не
соберёт мусор — а произойдёт это не сразу и по расписанию, которым мы не
управляем. Плюс переписывание меняет все хеши, и любые внешние ссылки на
коммиты ломаются.

Начать историю заново — быстрее и надёжнее. Кода это не касается: он
переносится ровно в том виде, в каком работает сейчас.

---

## Шаг 1. Подготовить снимок

В папке проекта:

```
npm run snapshot
```

Команда собирает папку `clean-snapshot/`: туда попадают только файлы под
контролем версий, и каждый проверяется на упоминания. Если что-то найдётся,
команда остановится и покажет файл и строку.

Что **не** попадает в снимок и почему:

- `node_modules`, `dist`, `release` — собираются заново командой сборки;
- `patches/` — архивы патчей ведут на адрес старого репозитория;
- `NEXUS.zip` — то же самое;
- `update-channel.json` — личный адрес канала обновлений, он у вас свой.

---

## Шаг 2. Создать пустой репозиторий

1. Откройте https://github.com/new
2. Имя — на ваш выбор (например, `NEXUS`).
3. **Не** ставьте галочки «Add a README», «Add .gitignore», «Choose a license» —
   репозиторий должен быть полностью пустым, иначе первый коммит придётся
   сливать с автоматическим.
4. Тип: **Private**, если исходники должны остаться закрытыми.

> Репозиторий релизов `NEXUS-releases` переносить не нужно: в нём лежат только
> собранные файлы, следов там нет. Проверено.

---

## Шаг 3. Залить снимок

В папке `clean-snapshot`:

```
git init -b main
git add .
git commit -m "NEXUS: первая версия"
git remote add origin https://github.com/<ваш-аккаунт>/<репозиторий>.git
git push -u origin main
```

**Проверьте имя автора** до коммита — оно попадёт в историю навсегда:

```
git config user.name "folyaken"
git config user.email "ваша почта на GitHub"
```

---

## Шаг 4. Проверить, что всё работает

В новой папке:

```
npm install
npm test           — ожидается 45/45
npm run channel:set -- https://github.com/folyaken/NEXUS-releases/releases/latest/download/
npm run release:win
```

Адрес канала обновлений задаётся заново: файл с ним намеренно не переносится.

---

## Шаг 5. Закрыть старый репозиторий

Только после того, как новый собрался и работает.

1. **Ссылки на патчи перестанут работать** — вы обновляетесь из нового
   репозитория, старые архивы больше не нужны.
2. Настройки → Danger Zone → **Delete this repository** (или Change visibility →
   Private, если хотите сохранить историю переписки для себя).

Ветки `arena/*` удалять по отдельности не нужно: они исчезнут вместе с
репозиторием.

---

## Что проверить в конце

- [ ] В новом репозитории одна ветка `main` и один коммит
- [ ] Автор коммита — вы, без соавторов
- [ ] `npm test` даёт 45/45
- [ ] `npm run release:win` собирает установщик
- [ ] Обновление из программы находит новую версию
- [ ] Старый репозиторий удалён или закрыт
