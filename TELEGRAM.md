# Канал NEXUS в Telegram

Документ о том, как вести канал: оформление, рубрики, боты, что публиковать
и в каком порядке. Написано так, чтобы можно было делать по пунктам.

Адрес канала: **https://t.me/nexus_flex**
Он же прописан в коде один раз — `src/main/community.ts`. Если канал переедет,
меняется только эта строка: интерфейс, меню значка возле часов и генератор
постов возьмут новый адрес сами.

---

## 1. Что настроить в первую очередь (30 минут)

| Шаг | Где | Что сделать |
| --- | --- | --- |
| Аватарка | Настройки канала → фото | `brand/nexus-avatar-512.png` |
| Название | Настройки | `NEXUS` — коротко, без слоганов в имени |
| Описание | Настройки | текст из раздела 2 |
| Адрес | Настройки → тип канала | публичный, короткая ссылка |
| Чат для обсуждений | Настройки → обсуждение | отдельная группа «NEXUS · Чат» |
| Закреплённый пост | первый пост | «Что такое NEXUS» + ссылка на скачивание |
| Реакции | Настройки → реакции | оставить 6–8 штук, не все подряд |
| Подпись авторов | Настройки | выключить, если пишете один — канал выглядит как продукт, а не как блог |

**Почему отдельный чат, а не комментарии в никуда.** Комментарии в Telegram
работают только если к каналу привязана группа. Без неё человек с проблемой
пишет в личку — вы отвечаете одному, остальные с той же проблемой не видят
ответа. С чатом один ответ работает на всех и накапливается база решений.

## 4. Рубрики: о чём писать, когда релизов нет

Главная ошибка канала продукта — публиковать только релизы. Между версиями
проходят недели, канал молчит, подписчики отписываются. Рубрики закрывают эту
дыру.

| Рубрика | Тег | Как часто | Пример |
| --- | --- | --- | --- |
| Новая версия | `#обновление` | по факту | «NEXUS 1.2.0: канал в программе, английский язык» |
| Как сделать | `#инструкция` | 1 раз в неделю | «Как включить VPN только для одной программы» |
| Что нового в разработке | `#разработка` | 1 раз в 2 недели | скриншот экрана, который делается сейчас |
| Разбор проблемы | `#решение` | по мере | «Не запускается TUN — чего не хватает» |
| Полезное о сети | `#ликбез` | 1 раз в 2 недели | «Чем PROXY отличается от TUN простыми словами» |
| Опрос | `#опрос` | 1 раз в месяц | «Каким режимом пользуетесь чаще?» |

**Ритм:** 2–3 поста в неделю. Реже — про канал забывают, чаще — отключают
уведомления.

**Правило текста:** пишем о том, что человек получит, а не о том, что мы
поменяли в коде. Не «переписан парсер подписок», а «подписки провайдеров, где
раньше показывалось ноль серверов, теперь читаются полностью».

## 5. Пост о релизе — теперь собирается сам

В проекте появился файл `CHANGELOG.md` и команда:

```
npm run post              — пост о текущей версии
npm run post -- 1.1.9     — пост о конкретной версии
npm run post -- --out post.txt
```

Скрипт берёт раздел версии из `CHANGELOG.md` и выдаёт готовый текст: заголовок,
пункты по разделам со значками, ссылка на установщик, напоминание про кнопку
обновления внутри программы. Остаётся скопировать в канал.

Порядок выпуска версии становится таким:

1. Дописать раздел версии в `CHANGELOG.md` — человеческим языком.
2. `npm test` → `npm run release:win`.
3. Выложить три файла в релиз `NEXUS-releases`.
4. `npm run post` → скопировать в канал.
5. Прикрепить к посту картинку (скриншот нового экрана) — посты с картинкой
   читают заметно чаще.

## 6. Боты: что реально пригодится

Не подключайте всё сразу. По одному, по необходимости.

### Обязательный минимум

**Бот обратной связи** (`@LivegramBot` или свой). Сообщения от пользователей
приходят вам одним потоком, ответ уходит обратно от имени бота. Нужен потому,
что в личку пишут с вопросами по установке, а личка быстро превращается в кашу.

**Антиспам в чате** (`@Shieldy_bot`, `@combot`). Как только у канала появляется
обсуждение, туда приходят боты с рекламой казино. Без защиты чат умирает за
неделю. Минимум: проверка новичка кнопкой, запрет ссылок первые сутки.

### Полезно позже

**Отложенный постинг** (`@ControllerBot`). Пост пишется, когда есть настроение,
а выходит в удобное время — 10:00 или 19:00 по Москве. Заодно ведёт статистику
по каждому посту.

**Аналитика** (`@TGStat_Bot`). Откуда пришли подписчики, какие посты дочитывают,
когда аудитория онлайн. Смотреть раз в месяц, не чаще: ежедневные графики только
нервируют.

**Свой бот-помощник** — самое сильное, но и самое трудоёмкое. Что в нём имеет
смысл:

- `/download` — ссылка на последнюю версию и её номер;
- `/version` — какая версия сейчас актуальна;
- частые проблемы кнопками: «не запускается TUN», «подписка не подгружается»,
  «Windows ругается на установщик»;
- уведомление о выходе новой версии тем, кто подписался.

Такой бот снимает 80% однотипных вопросов. Делается на `node-telegram-bot-api`
или `grammy` за вечер, размещается на любом дешёвом сервере. Если решите
делать — скажите, соберу заготовку в этом же репозитории.

### Чего не делать

- Не ставить бота, который сам постит новости из RSS: канал заполняется мусором.
- Не включать капчу из десяти шагов: люди уходят, не дойдя до чата.
- Не покупать подписчиков. Мёртвая аудитория обрушивает охваты: Telegram
  показывает пост тем, кто читает, а таких не будет.

## 7. Автопубликация релизов из GitHub

Когда надоест копировать пост руками, это делается одним действием GitHub
Actions: при публикации релиза в `NEXUS-releases` бот сам отправляет в канал
текст с номером версии и ссылкой.

Что нужно:

1. Создать бота у `@BotFather`, получить токен.
2. Добавить бота администратором канала (право «публиковать сообщения»).
3. Положить токен и `chat_id` в секреты репозитория.
4. Добавить workflow, который на событие `release: published` отправляет
   `sendMessage`.

Делать это стоит после того, как выйдет ещё две-три версии вручную: пока текст
поста меняется от релиза к релизу, автоматика только мешает.

## 8. Как набирать первых подписчиков

По убыванию отдачи:

1. **Ссылка внутри программы.** Уже сделана: раздел «О программе» и меню значка
   возле часов. Это самый качественный источник — приходят те, кто уже
   пользуется.
2. **Ссылка в установщике и в README** репозитория с релизами.
3. **Тематические чаты и форумы** про обход блокировок: не реклама, а ответ по
   делу с упоминанием программы. Прямая реклама выглядит как спам и работает
   хуже.
4. **Ответы на вопросы** на profile-форумах и в комментариях там, где ищут
   решение проблемы, которую NEXUS закрывает.
5. **Telegram Ads** — только когда канал уже живой и есть что показать. Пустой
   канал с рекламным трафиком даёт отписки.

## 9. Что важнее любых ботов

**Отвечать.** Канал продукта живёт ответами. Человек написал «не работает TUN»,
получил ответ за час — он остался. Не получил — удалил программу и рассказал об
этом знакомым.

**Не пропадать.** Два месяца тишины хуже, чем неидеальные посты раз в неделю.

**Честно писать о проблемах.** «В 1.2.0 сломался автозапуск, чиним, выпустим
завтра» вызывает больше доверия, чем молчание.
