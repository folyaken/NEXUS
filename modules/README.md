# NEXUS modules

Исполняемые файлы и связанные конфигурации хранятся в `modules/bin`. Каждый файл `*.module.json` описывает один внешний модуль; относительные пути разрешаются от папки `modules`.

NEXUS запускает процессы без shell (`shell: false`), передаёт stdout/stderr в `log_file`, отслеживает PID и завершает дерево процесса при остановке. Обновление рабочего модуля блокируется, а запуск блокируется на время замены файлов — это защищает бинарники от частичной перезаписи. Загрузчик сначала обращается к GitHub напрямую, затем при необходимости использует разрешённые зеркала; размер, формат и опубликованный GitHub SHA-256 проверяются до установки.

Для сервиса можно задать локальную TCP-проверку готовности. В таком случае статус `running` появляется только после того, как процесс пережил начальный запуск и порт действительно начал принимать подключения:

```json
{
  "id": "my-module",
  "name": "My module",
  "description": "Local network helper",
  "enabled": false,
  "executable": "./bin/my-module.exe",
  "args": [],
  "status": "stopped",
  "category": "other",
  "icon": "◈",
  "pid": null,
  "log_file": "./logs/my-module.log",
  "working_dir": "./bin",
  "healthcheck": {
    "type": "tcp",
    "host": "127.0.0.1",
    "port": 9000,
    "timeout_ms": 10000
  }
}
```

`healthcheck.host` намеренно ограничен loopback-адресами. Не добавляйте в манифест секреты, токены или ссылки подписок.

## TG WS Proxy

NEXUS запускает официальный tray-бинарник с `--portable`. Конфигурация и настоящий журнал upstream находятся в `modules/bin/TgWsProxy_data`; встроенная проверка обновлений TG WS Proxy отключается, потому что загрузкой проверенных GitHub assets управляет NEXUS. Рабочий локальный MTProto-порт — `127.0.0.1:1443`.

Для Windows x64 выбирается функционально идентичная compatibility-сборка upstream, устраняющая известные ранние сбои PyInstaller/`_tkinter`; для ARM64 и 32-bit Windows выбираются отдельные assets. На каждый запуск создаётся отдельный системный временный каталог, поэтому остатки `_MEI` от прошлого аварийного запуска не конфликтуют с новым процессом.

Используйте только доверенные бинарные файлы и проверяйте их происхождение.
