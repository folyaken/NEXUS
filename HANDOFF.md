## Рабочий цикл (соблюдать каждый раз)

1. Правки → `npm test` (52/52) → `npm run build`.
2. Поднять `version` и `patchLevel` в `package.json`, дописать раздел в `CHANGELOG.md`.
3. `rm -f patches/*.zip` → `node scripts/pack-patch.cjs --name <slug> --files <файлы> --out patches`
4. Коммит → `node scripts/pack-flat.cjs` → коммит → `git push -q origin arena/01a001df-nexus`
5. Проверить ссылку: `curl -s -o /dev/null -w "HTTP %{http_code}" --max-time 25 "https://github.com/folyaken/NEXUS/raw/arena/01a001df-nexus/patches/<имя>.zip"` — **HTTP 302 это норма**.
6. `present_file` на архив.
7. Ответ: ссылка + что поменял + как поставить + **чек-лист для ТГ**.

## Команды проекта

| Команда | Что делает |
|---|---|
| `npm test` | 52 набора тестов |
| `npm start` | запустить программу (сборку вызовет сам) |
| `npm run build` | **только код**, `.exe` не создаёт |
| `npm run release:win` | **собрать установщик** → `release/`: `.exe`, `latest.yml`, `.blockmap` |
| `npm run theme:crimson` / `theme:graphite` | пересобрать тему (встроено в build) |
| `npm run post` | текст поста из CHANGELOG |

Различай: **«проверить»** = `npm test` + `npm start`; **«собрать установщик»** = `npm run release:win`. Не называй `npm run build` сборкой — я на этом уже путался.

## Ловушки песочницы (проверено на опыте)

- **`node_modules` не сохраняется между сессиями.** Каждый раз:
  `cd /home/user/NEXUS && ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm install --no-audit --no-fund --fetch-retries=8`
- **`npm install` затирает папку `build/`** (`installer.nsh`, `no-sign.cjs`) → падают 5 тестов. Лечится: `git checkout FETCH_HEAD -- build`
- **Локальная папка периодически откатывается к старому коммиту `bfef363`.** Признак: `git push` отклоняется как non-fast-forward. Решение: сохранить правки в `/tmp/keepN/`, затем `git fetch -q origin arena/01a001df-nexus && git reset -q --hard FETCH_HEAD`, вернуть файлы и **заново** поднять версию от актуальной.
- **electron-builder в песочнице не запускается** — установщик собираю только я.
- `npm audit fix --force` запускать **нельзя**. 14 уязвимостей — все в devDependencies, в `.exe` не попадают.
- Вложенные файлы иногда не доходят (`/home/user/uploads/` пустой) — скажи об этом, не догадывайся.
- Для картинок: шрифты приложения (`assets/fonts/*.woff2`) надо конвертировать через `fonttools` (`pip install --break-system-packages fonttools brotli`), эмодзи и стрелки `→` в подмножество не входят — рисовать фигурами.

## Архитектура тем (важно)

Три оформления: **Индиго** (основное), **Графит** (лаванда), **Багровое**.

Графит и Багровое **не пишутся руками** — они генерируются из `styles.css` скриптами `scripts/graphite-theme.cjs` и `scripts/crimson-theme.cjs` в отдельные файлы `graphite.css` / `crimson.css`, которые подключаются в `main.tsx` **после** основного стиля.

Причина: в интерфейсе 800+ правил с прямо прописанными цветами. Руками их обходили меньше чем наполовину — тумблеры и логотип оставались от «Индиго». Если правишь цвет — правь основной стиль или функцию `repaint()`, потом `npm run build`.

Состояния (успех / предупреждение / ошибка) должны **оставаться различимыми** в любой теме — иначе по цвету не понять, что случилось.
