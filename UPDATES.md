# Обновление одной кнопкой

Чтобы пользователи не устанавливали каждую версию вручную, нужен **канал
обновлений** — адрес в интернете, откуда программа берёт сведения о новой
версии и сам установщик.

Настраивается один раз. Дальше выпуск новой версии — три действия.

---

## Шаг 1. Создать публичный репозиторий для сборок

Исходный код остаётся закрытым. Публичным будет только место для готовых
файлов.

1. Откройте https://github.com/new
2. Имя: **`NEXUS-releases`**
3. Тип: **Public** (обязательно — иначе программа не сможет скачать обновление
   без пароля)
4. **Поставьте галочку `Add a README file`** — это важно
5. Нажмите **Create repository**

> **Почему нужен README.** Без единого файла репозиторий остаётся пустым, в нём
> нет ветки `main`. Тег релиза создавать не от чего, и кнопка **Publish
> release** остаётся серой. Если репозиторий уже создан пустым, просто добавьте
> любой файл через **creating a new file** на главной странице.

> **Почему публичный.** Для закрытого репозитория пришлось бы положить ключ
> доступа внутрь установщика. Любой желающий извлёк бы его и получил доступ ко
> всем вашим репозиториям. В публичном лежат только собранные файлы, которые вы
> и так раздаёте.

## Шаг 2. Указать адрес канала

В папке проекта выполните один раз:

```
npm run channel:set -- https://github.com/folyaken/NEXUS-releases/releases/latest/download/
```

Замените `folyaken` на своё имя пользователя, если оно другое.

Проверить, что адрес сохранён:

```
npm run channel
```

Адрес хранится в файле `update-channel.json` в корне проекта.

## Выпуск новой версии

### 1. Поднять номер версии

В `package.json` измените `version`, например `1.1.1` → `1.1.2`.

Это обязательно: программа сравнивает номера и предлагает обновление, только
если на сервере версия **выше** установленной.

### 2. Собрать выпуск

```
npm run release:win
```

В конце команда покажет список файлов, которые нужно выложить.

### 3. Выложить файлы

1. Откройте `https://github.com/folyaken/NEXUS-releases/releases/new`
2. **Choose a tag** → введите `v1.1.2` → *Create new tag*
3. Прокрутите страницу вниз до полосы **«Attach binaries by dropping them here
   or selecting them»** и перетащите туда **три файла** из папки `release`:

   > Не в поле «Describe this release» — туда `.exe` не принимается, GitHub
   > покажет «We don't support that file type».

   - `NEXUS-Setup-1.1.2.exe`
   - `latest.yml`
   - `NEXUS-Setup-1.1.2.exe.blockmap`
4. Нажмите **Publish release**

> **`latest.yml` обязателен.** Именно в нём записано, какая версия вышла и какой
> у файла размер и контрольная сумма. Без него программа не увидит обновление.
>
> **`.blockmap` ускоряет загрузку.** С ним докачиваются только изменившиеся
> части, а не весь установщик заново.
>
> **Не переименовывайте файлы.** В имени нет пробелов намеренно: GitHub
> заменяет пробелы точками, и программа стала бы искать обновление по
> несуществующему адресу.

## Как это выглядит у пользователя

1. Открывает **О программе** → нажимает **Проверить**
2. Видит «Доступна версия 1.1.2» → нажимает **Скачать**
3. Нажимает **Перезапустить и установить**

Программа сама остановит VPN и модули, вернёт системные настройки сети,
установит новую версию и запустится заново. Настройки, профили и подписки
сохраняются.

---

## Что важно знать

**Первая версия с обновлением рассылается вручную.** Механизм появляется только
в той сборке, где канал уже настроен. Друг ставит её один раз обычным способом,
дальше обновления идут сами.

**Устанавливать обновление нужно от имени администратора.** Программа и так
запрашивает права при запуске, поэтому дополнительных действий не требуется.

**Понижение версии не поддерживается.** Если выложить версию ниже установленной,
программа сообщит, что обновлений нет.

**Проверка подлинности выполняется всегда.** Контрольная сумма из `latest.yml`
сверяется с загруженным файлом: подменённый или повреждённый установщик не
запустится.

**Канал работает только по HTTPS.** Адрес с `http://` программа отклонит — по
незащищённому соединению обновление можно подменить.

## Если что-то пошло не так

| Что показывает программа | Причина и решение |
| --- | --- |
| «Канал обновлений не настроен в этой сборке» | Сборка сделана без канала. Выполните `npm run channel:set` и соберите заново командой `npm run release:win` |
| «На сервере обновлений нет сведений о новой версии» | В релиз не приложен `latest.yml` |
| «Сервер обновлений недоступен» | Нет интернета либо репозиторий не публичный |
| «Проверка подлинности не пройдена» | Файлы в релизе от разных сборок. Соберите заново и выложите все файлы вместе |
| «Установлена последняя версия», хотя вышла новая | Не поднят номер версии в `package.json` |
